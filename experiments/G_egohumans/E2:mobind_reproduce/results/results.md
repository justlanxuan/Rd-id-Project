# MoBInd official reproduction on EgoHumans

## 1. Purpose
Use a clean, isolated environment (`mobind_repro`) to reproduce the published MoBInd evaluation numbers on the EgoHumans dataset for:
- cross-modal retrieval (IMU ↔ video),
- egocentric body localization (person + limb),
- temporal synchronization (person-level and video-level).

## 2. Reproduction steps

```bash
bash experiments/G_egohumans/E2:mobind_reproduce/scripts/A1_run_full_repro.sh
```

The script:
1. Activates the `mobind_repro` conda environment.
2. Builds the contrastive cache, multi-person localization cache and sync cache.
3. Runs `eval_retrieval.py`, `eval_localization.py`, and `eval_sync_egoh.py` (both `--task person` and `--task video`).

## 4. Code fixes applied to MoBInd

To make the official code runnable out-of-the-box, the following local fixes were applied:

- `preprocess/EgoHumans/cache.py`, `cache_multi_person.py`: cast `numpy.int64` window indices to Python `int` before `json.dump`.
- `builder/build_model.py`: removed imports for undefined modules (`ContrastiveStage2Module`, `ContrastiveBaselineModule`, `ContrastiveConcatBaselineModule`) and fixed the `ConvFormer` import path (`models.conv_former` instead of `models.imu_encoder.conv_former`).
- `eval_sync_egoh.py`: adapted `eval_person_level` for multi-person cache arrays `(P, T, ...)` and removed a duplicated `gt_offsets.append(offset)` that caused a length mismatch.

## 9. Observations and caveats

- Retrieval numbers match the high R@1 regime reported in the MoBInd paper for EgoHumans.
- Localization is dominated by person-level accuracy; limb-level accuracy is lower but consistent with the task difficulty.
- Sync evaluation required multi-person adaptation. Person-level numbers split each multi-person sample into independent person instances. Video-level aggregates predictions across persons per sample.
- No training was performed; all numbers use the provided pre-trained checkpoints.
